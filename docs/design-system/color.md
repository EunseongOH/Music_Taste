# Sortify 색 시스템 — 로고 기반 시안

> **시안 (2026-09-22, 브랜치 `design/logo-theme`). 채택 전이다.** develop 의 `color.md`(cream · navy · 벽돌빛 danger)는 이 브랜치에서 `legacy` 테마로 그대로 살아 있다.
> 토큰 정의: `src/app/globals.css` · 비교 화면: `/dev/theme-lab` · 짝 문서: `typography.md`(워드마크 6장), `dialogs.md`, `ux-writing.md`

새 로고(파란 하트 + 민트 음표 + 주황 점, 유리 질감 그라데이션)에 서비스 톤을 맞춘다. 참고한 체계는 토스 TDS 다 — 흰 바탕, 회색 단계로 나눈 면, 파랑 하나를 행동 색으로.

## 1. 원칙

1. **로고의 밝은 색은 그림에만 쓴다.** 로고 파랑(#4C9EFE~#4063FB)·민트·하늘은 흰 글자·흰 바탕 어느 쪽과도 대비가 부족하다(4장). 버튼과 글자에는 같은 색상(hue 229°)을 **어둡게 내린 파랑**을 쓴다.
2. **행동 색은 파랑 하나, 강조는 주황 하나.** 로고의 주황 점이 곧 지금의 `point` 다. 역할은 그대로 — 선·면에만, 글자에는 `point-ink`.
3. **바탕은 색이 없어야 한다.** 앨범 재킷이 화면의 색을 맡는다. 크림 바탕과 종이 결 질감은 재킷 색을 누렇게 물들인다.
4. **빨강은 잃는 행동에만.** 크림 위에서 고른 벽돌빛(#9E3B2F)은 흰 바탕에서 탁해 보여 맑은 빨강으로 바꾼다.
5. **작은 글자는 4.5:1 이상, 모든 바탕에서.** 보조 글자(`navy/70`)까지 포함이다. 이 조건이 `navy` 값을 정했다.
6. 장식 아이콘을 두지 않는다 · 역할로 고른다 — develop 문서 그대로.

## 2. 토큰

이름은 1차 시안에서 그대로 둔다(1,196곳). 값은 테마마다 다르다.

|---|---|---|---|---|
| `cream` | 화면·시트·카드 바탕 | #F5F2ED | **#FFFFFF** | **#F3F8FF** |
| `--background` | 앱 바깥 바탕(데스크톱 여백) | #EAE2D6 | #F2F4F6 | #E6F1FD |
| `navy` | 기본 글자, 주 버튼 면, 선(`/10`), 옅은 면(`/5`) | #1A2A6C | **#172D80** | #172D80 |
| `charcoal` | 본문 대체(레거시) | #2D3436 | #333D4B | #333D4B |
| `point` | 강조 선·면. **글자 금지** | #E67E22 | **#FD7E3E** | #FD7E3E |
| `point-ink` | 강조 글자 | #A65309 | **#C2410C** | #C2410C |

## 3. 바탕 두 안

| | A. toss-white (기본안) | B. sky-tint (비교용) |
|---|---|---|
| 바탕 | 흰색. 구역은 회색 면(#F2F4F6)과 선(#E5E8EB)으로 나눈다 | 로고의 하늘빛을 3% 남짓 깐 바탕(#F3F8FF) |
| 재킷 색 | 그대로 보인다 | 전체가 살짝 차가워진다. 따뜻한 재킷이 뜬다 |
| 흰 카드(`bg-white`) | **바탕과 같아져 경계가 사라진다** — 7장 | 카드가 살아 있다 |
| 주황 | 가장 선명 | 파랑 바탕과 보색이라 더 튄다 |
| 토스 미니앱 | 토스 화면과 이어진다 | 미니앱 안에서 혼자 색이 있다 |
| 위험 | 밋밋해질 수 있다. 회색 면 설계를 다시 해야 한다 | "파란 서비스"로 굳는다. 되돌리기 어렵다 |

권고: **A.** 음악 서비스는 재킷이 주인공이고, 토스 미니앱이 주 채널이다. B 의 장점(카드 경계)은 A 에서 회색 면을 쓰면 해결된다.

## 5. 2차 제안 — 글자와 버튼을 나눈다

지금 `navy` 하나가 **본문 글자**와 **주 버튼 면**을 함께 맡는다. 그래서 버튼을 로고처럼 선명한 파랑으로 올리면 본문이 전부 파래지고, 본문을 읽기 좋게 어둡게 두면 버튼이 남색으로 가라앉는다. TDS 는 이 둘을 나눈다.

| 새 토큰 | 값(A) | 역할 | TDS 대응 |
|---|---|---|---|
| `ink` | #191F28 | 본문·제목 글자 | grey900 |
| `brand` | #2B4FD8 | 주 버튼 면, 링크, 선택 상태 | blue500 (#3182F6 을 대비 때문에 어둡게) |
| `fill` | #F2F4F6 | 옅은 면(지금의 `navy/5`) | grey100 |
| `line` | #E5E8EB | 구분선(지금의 `navy/10`) | grey200 |

토큰은 `globals.css` 에 이미 있고 `/dev/theme-lab` 의 "2차 제안" 상자에서만 쓴다. 채택하면 `navy` 1,196곳을 `ink`·`brand` 로 가르는 작업이 따라온다(글자 → ink, `bg-navy` → brand). SpaceUI 의 버튼 클래스부터 바꾸면 시트·스페이스·아카이브는 한 번에 넘어간다.

## 6. 버튼 · 확인 창

develop 문서와 같다. `primaryButton`(navy 면) · `secondaryButton`(navy/5) · `dangerButton`(danger/10 면 + danger 글자) · `textLink`. 새 테마에서 `dangerButton` 은 옅은 분홍 면 + 빨강 글자가 된다. 팝업·시트·토스트 규칙은 `dialogs.md`.

## 7. 새 톤에서 어색한 곳 (1차에서는 고치지 않는다)

토큰 클래스 1,196곳은 테마를 따라온다. 아래는 **색을 직접 적어서 안 따라오는 곳**이다.

| 곳 | 무엇이 남나 |
|---|---|
| 홈 모드 카드 면, 언어 전환 알약 (`page.tsx`) | 크림빛 면(#FAF7F2 · #F1EADC 계열)이 흰 바탕 위에 누렇게 뜬다 |
| `#F5F2ED` 직접 표기 15곳 (`tracks`, `explore`, `LoginModal`, `genres` 등) | 시트·모달 바탕이 크림으로 남는다 → `bg-cream` |
| `#E67E22` 직접 표기 6곳 | 옛 주황이 새 주황(#FD7E3E)과 섞인다 → `point` |
| `bg-white` 67곳 | A 안에서 바탕과 같아져 카드 경계가 사라진다. `bg-white/60` 같은 반투명 면도 마찬가지 → 회색 면(`fill`)이나 선으로 다시 설계 |
| `border-[3px] border-navy` 굵은 테두리 카드·모달 | 크림 + 남색의 "레코드 가게" 분위기를 만드는 장치. 흰 바탕에서는 무겁다. TDS 식은 테두리 없이 면과 그림자 |
| 홈의 턴테이블 일러스트, LP 그래픽 | 토큰을 써서 색은 따라오지만, 선화 스타일이 유리 질감 로고와 결이 다르다 |
| 취향표 템플릿(`TasteTemplates`) · 저장 이미지 | 자체 팔레트. 범위 밖. 크림 카드가 새 화면 위에서 어떻게 보이는지는 `/dev/result-lab` 에서 확인 |
| `red-500` 계열 11곳 | develop 의 옮길 곳 목록과 같다 → `danger` |
| 카카오 #FEE500, 인스타그램 그라데이션 | 브랜드 색. 예외로 둔다 |
| `genres/page.tsx` 19곳 | 믹스 매치 격리 중이라 보이지 않는다. 되살릴 때 같이 |

파일별 직접 표기 수(취향표 템플릿 제외): genres 19 · ResultScreen 16 · tracks 10 · LoginModal 9 · explore 5 · popup-login 5 · 그 밖 15.

## 8. 구현 메모

- `@theme inline` 의 토큰 값을 `var(--t-*)` 참조로 두고, 실제 값은 `:root`(=legacy) · `[data-theme="toss-white"]` · `[data-theme="sky-tint"]` 에 둔다. `text-navy/70` 은 `color-mix(in oklab, var(--t-navy) 70%, transparent)` 로 풀려 테마를 바꿔도 그대로 먹는다(빌드된 CSS 로 확인).
- `color-mix` 를 모르는 브라우저(Chrome 111 · Safari 16.2 미만)에서는 불투명도 없이 원색으로 나온다. 이전에는 Tailwind 가 계산해 둔 hex 가 대체값이었다. **채택할 때 테마를 하나로 굳히면 값을 다시 직접 적어 이 문제를 없앤다.**
- `<html data-theme>` 는 `layout.tsx` 의 부트 스크립트가 `?theme=` 또는 `localStorage.sortify_theme` 으로 붙인다. 값이 없으면 아무것도 붙지 않아 legacy 그대로다.
- 스크린샷: `node scripts/theme-shots.mjs <폴더>` (dev 서버 3300). Spotify 를 부르지 않는 화면만 찍는다.

## 9. 결정이 필요한 것

1. 바탕 A / B.
2. 1차(이름 유지, 값만 교체)로 갈지, 2차(`ink` · `brand` 분리)까지 갈지. 2차가 로고와 가장 잘 맞지만 작업량이 크다.
3. 굵은 남색 테두리 카드와 턴테이블 선화를 유지할지. 색만 바꾸면 "크림 없는 옛 디자인"이 된다.
4. 취향표 저장 이미지의 팔레트를 같이 바꿀지. 이미 공유된 이미지와 달라진다.
5. 워드마크 서체 — `typography.md` 6장.
