# Sortify 색 시스템 — 로고 기반 시안

> **시안 (2026-09-22, 브랜치 `design/logo-theme`). 채택 전이다. 기준 테마는 B(sky-tint), 2차(글자 ink · 버튼 brand) 적용 중.** develop 의 `color.md`(cream · navy · 벽돌빛 danger)는 이 브랜치에서 `legacy` 테마로 그대로 살아 있다.
> 토큰 정의: `src/app/globals.css` · 비교 화면: `/dev/theme-lab` · 짝 문서: `typography.md`(워드마크 6장), `dialogs.md`, `ux-writing.md`

새 로고(파란 하트 + 민트 음표 + 주황 점, 유리 질감 그라데이션)에 서비스 톤을 맞춘다. 참고한 체계는 토스 TDS 다 — 흰 바탕, 회색 단계로 나눈 면, 파랑 하나를 행동 색으로.

## 1. 원칙

1. **로고의 밝은 색은 그림에만 쓴다.** 로고 파랑(#4C9EFE~#4063FB)·민트·하늘은 흰 글자·흰 바탕 어느 쪽과도 대비가 부족하다(4장). 버튼과 글자에는 같은 색상(hue 229°)을 **어둡게 내린 파랑**을 쓴다.
2. **행동 색은 파랑 하나, 강조는 주황 하나.** 로고의 주황 점이 곧 지금의 `point` 다. 역할은 그대로 — 선·면에만, 글자에는 `point-ink`.
3. **바탕은 색이 없어야 한다.** 앨범 재킷이 화면의 색을 맡는다. 크림 바탕과 종이 결 질감은 재킷 색을 누렇게 물들인다.
4. **빨강은 잃는 행동에만.** 크림 위에서 고른 벽돌빛(#9E3B2F)은 흰 바탕에서 탁해 보여 맑은 빨강으로 바꾼다.
5. **작은 글자는 4.5:1 이상, 모든 바탕에서.** 보조 글자(`navy/70`)까지 포함이다. 이 조건이 `navy` 값을 정했다.
6. 장식 아이콘을 두지 않는다 · 역할로 고른다 — develop 문서 그대로.
7. **파랑은 아껴 쓴다.** 새 톤에서 `brand` 파랑과 로고의 빛은 **행동(주 버튼·선택 상태)과 카드의 옅은 악센트**에만 쓴다. 장식 그림(턴테이블 등)과 바탕에는 겹쳐 쓰지 않는다. 주황(`point`)은 작은 악센트로만 — 점·밑줄·작은 배지. 근거: 사용자 피드백 "서비스 전체가 너무 메인 색상에 파묻힌 느낌이 들어서 별로야"(2026-09-22). 바탕이 이미 하늘빛이므로 한 화면에서 파랑이 놓이는 자리는 셋을 넘기지 않는다(홈: 배지 글자 · 카드 모서리의 빛 · 시작하기).

## 3. 바탕 두 안

| | A. toss-white (기본안) | B. sky-tint (비교용) |
|---|---|---|
| 바탕 | 흰색. 구역은 회색 면(#F2F4F6)과 선(#E5E8EB)으로 나눈다 | 로고의 하늘빛을 3% 남짓 깐 바탕(#F3F8FF) |
| 재킷 색 | 그대로 보인다 | 전체가 살짝 차가워진다. 따뜻한 재킷이 뜬다 |
| 흰 카드(`bg-white`) | **바탕과 같아져 경계가 사라진다** — 7장 | 카드가 살아 있다 |
| 주황 | 가장 선명 | 파랑 바탕과 보색이라 더 튄다 |
| 토스 미니앱 | 토스 화면과 이어진다 | 미니앱 안에서 혼자 색이 있다 |
| 위험 | 밋밋해질 수 있다. 회색 면 설계를 다시 해야 한다 | "파란 서비스"로 굳는다. 되돌리기 어렵다 |

처음 권고는 A 였다(재킷이 주인공, 토스 미니앱이 주 채널). **사용자는 B 로 기울었다(2026-09-22)** — 이후 작업과 스크린샷은 sky-tint 기준이다. B 에서 지켜볼 것: 따뜻한 재킷이 차가운 바탕에서 뜨는지, 주황이 과하게 튀는지, 토스 미니앱 안에서 이질감이 없는지. A 와 legacy 는 비교용으로 남겨 둔다.

## 5. 2차 — 글자와 버튼을 나눈다 (적용 중)

지금 `navy` 하나가 **본문 글자**와 **주 버튼 면**을 함께 맡는다. 그래서 버튼을 로고처럼 선명한 파랑으로 올리면 본문이 전부 파래지고, 본문을 읽기 좋게 어둡게 두면 버튼이 남색으로 가라앉는다. TDS 는 이 둘을 나눈다.

| 새 토큰 | 값(A) | 역할 | TDS 대응 |
|---|---|---|---|
| `ink` | #191F28 (B: #18213B) | 본문·제목 글자, 어두운 면(토스트) | grey900 |
| `brand` | #385BF0 | 주 버튼 면, 링크, 선택 상태 | blue500 (#3182F6 은 흰 글자 3.71 이라 그대로 못 쓴다) |
| `fill` | #F2F4F6 | 옅은 면(지금의 `navy/5`) | grey100 |
| `line` | #E5E8EB | 구분선(지금의 `navy/10`) | grey200 |

**글자 클래스는 건드리지 않았다.** `navy` 토큰의 값을 ink 로 내리고, 버튼 면만 `bg-brand` 로 뺐다. 그래서 `text-navy` · `border-navy/10` · `bg-navy/5` 1,100여 곳은 그대로다.

**legacy 에서는 `brand` = `ink` = `navy`(#1A2A6C)** 라 클래스를 바꿔도 지금 운영 화면과 픽셀 단위로 같다(홈 스크린샷 비교 차이 0, 내보내기 기준선 7/7 동일). 같은 이유로 주 버튼을 `primaryButton` 으로 통일하지는 않았다 — 모양(높이·모서리·여백)이 달라 legacy 가 바뀐다. 클래스 통일은 채택 뒤 별도 작업이다.

면·배지를 brand 로 올리지 않은 이유
- **맨 위로 버튼**(explore): 화면의 주 행동이 아니라 보조 도구다. 주 버튼("다음으로 넘어가기")과 같은 파랑이면 둘이 경쟁한다.

## 6. 버튼 · 확인 창

`primaryButton`(**brand 면**) · `secondaryButton`(navy/5) · `dangerButton`(danger/10 면 + danger 글자) · `textLink`. 새 테마에서 `dangerButton` 은 옅은 분홍 면 + 빨강 글자가 된다. 팝업·시트·토스트 규칙은 `dialogs.md`.

#### 사용자 결정과 "판 크기" 피드백의 진짜 뜻 (2026-09-22, 세 번째)

- 카드 빛: **50%(half) 확정.** `ModeCard` 기본값. 100% · 30% 는 `#glow-levels` 비교용.
- 재킷이 없을 때의 라벨: **B(작은 단색 주황 라벨, LP 의 30%) 확정.** A 는 시안에만.
- "판이 좀 더 작아도 되지 않나"의 뜻은 **판을 줄이라는 것이 아니었다.** 사용자: "실제 턴테이블은 LP 가 올라가면 그 원형 판의 면적 대부분을 LP 가 차지했던 것 같아서, 그런 부분에서 현실성이 떨어진다." 이전 그림은 큰 원(홈이 있는 면)이 플래터로, 가운데 재킷이 LP 로 읽혔다.

고친 것 — `Turntable1` 을 **플래터 + LP 두 겹**으로.

| 겹 | 모양 |
|---|---|
| 플래터 | 받침 위의 옅은 중립색 원. LP 바깥으로 **6px 테**만 보인다 |
| LP | 플래터 지름의 **91%**. 흰 면 + 또렷한 가장자리(선 + 아주 옅은 그림자) + 홈 세 줄. 재킷은 이 위에 올라온다 |

재킷이 올라오는 방식 두 안 (`#turntable-refine`)

| 안 | 모양 | 장단 |
|---|---|---|
| (가) 픽처 디스크 | 재킷이 LP 면 전체(지름 124). 가운데 스핀들 구멍, 판이라는 것이 읽히게 아주 옅은 홈 두 줄 | 사용자 말에 가장 가깝고 재킷이 가장 크다(운영의 라벨 64 → 124). 회전하면 재킷 전체가 돈다 |
| (나) 홈이 있는 LP + 큰 라벨 | 재킷이 LP 의 62%(지름 77), 바깥은 홈 | LP 다운 모양이 남는다. 재킷은 (가)보다 작다 |

전체 크기 — **받침 안(플래터 136 · LP 124)을 제안**한다. 운영과 같은 크기(플래터 176 · LP 160, 받침 위아래로 넘침)는 비교용.
이유: ① LP 가 이제 채워진 면이라 같은 지름이어도 선화였던 운영보다 훨씬 무겁게 보인다 — 홈에서는 장식이라는 원칙과 어긋난다. ② (가)에서는 재킷 지름이 이미 운영 라벨의 두 배(64 → 124)라, 재킷을 크게 보여 주려고 판을 키울 이유가 없다. ③ 받침을 넘치지 않으면 "시작하기"와의 간격이 일정해진다.

**`LPPlayer` 에 옮길 때 바뀌는 범위** (사용자가 시안을 확인한 뒤)
- 구조는 그대로 된다. 운영 `LPPlayer` 는 이미 바깥 링(176) > 회전하는 판(160) > 홈 3줄 + 라벨(64, 재킷은 여기에 `next/image`) 의 중첩이다. 바깥 링 → 플래터, 회전하는 판 → LP, 라벨 → 재킷 자리로 **같은 요소에 `newtone:` 클래스만 더한다.** 요소를 새로 만들거나 없애지 않는다.
- 운영은 재킷이 올라오면 판을 어둡게(`bg-[#1a1a1a]`) 하고 재킷을 80% 농도로 그린다 → 새 테마에서는 `newtone:bg-white`, `newtone:opacity-100`. (가)라면 라벨 요소에 `newtone:w-full newtone:h-full newtone:border-0`.
- prop 하나 추가: `emphasis?: "quiet" | "normal"`(기본 quiet). 월드컵 화면만 `normal` 을 넘긴다.
- legacy 는 클래스를 건드리지 않으므로 픽셀 단위로 그대로다.

#### 턴테이블 확정 — 실제 `LPPlayer` 에 반영 (2026-09-22, 사용자가 직접 결정)

| 결정 | 사용자 말 |
|---|---|
| 재킷은 **(가) 픽처 디스크** | "가 픽처 디스크 형식" |
| 전체 크기는 **받침 안**(플래터 136 · LP 124) | "전체 크기를 받침 안으로 했으면 좋겠어" |
| **월드컵에서도 조용하게** | "월드컵에서도 사실 메인 요소는 아니니까 그렇게 강조되지는 않았으면 좋겠어" |

- 그래서 홈용/월드컵용을 가르는 `emphasis` prop 은 **만들지 않았다.** 모양은 하나(시안의 quiet)다. 필요해지면 그때 더한다.
- `src/components/LPPlayer.tsx` 한 파일. legacy 클래스는 한 글자도 바꾸지 않았고, 새 테마의 모양은 같은 요소에 `newtone:` 변형으로만 덧붙였다. 새로 생긴 요소는 픽처 디스크의 옅은 홈 두 줄(`hidden newtone:block`)뿐이다. `worldcup/page.tsx` 는 고치지 않았다.
- **톤암은 재생 중 돌아가는 LP 위에 있다**(사용자: "돌아가는 연출까지 할 거라면, 톤암이 돌아가는 LP 위에 있어야 해"). 새 테마에서는 회전축을 받침 오른쪽 끝이 아니라 **판 중심 기준**(`left: calc(50% + 98px)`, sm `+128px`)으로 잡아 받침 너비와 상관없이 같은 자리에 내려온다. 43° 로 내려오면 헤드 중심이 LP 중심에서 **반지름의 0.67**(400px: 41/62, 768px: 55/84) — 바깥쪽 1/3, 첫 곡 자리다. 정지 상태에서는 LP 밖에 수직으로 서 있고(1.8배 거리), 헤드는 받침 안에 머문다. 판·재킷보다 위(z-20)라 픽처 디스크의 그림 일부를 가린다. 색은 중립(흰 면 + 옅은 선), 그림자는 LP 위에 떠 있다는 것이 읽힐 정도로만.
- 운영(legacy)의 톤암은 건드리지 않았다. 참고: **운영에서는 재생 중에도 헤드가 판 위에 올라오지 않는다.** 회전축이 받침 오른쪽 끝 기준이고 각도가 25° 라, 400px 화면에서 헤드 중심이 판 중심에서 반지름의 1.17배(판 바로 바깥), 받침이 최대 너비(512)일 때는 1.43배 거리에 멈춘다. 같은 지적이 운영에도 해당한다.
- 월드컵에서 곡을 고르면 페이지가 받침에 주황 테두리·그림자(`border-point shadow-…`)를 준다. 새 테마에서는 `newtone:` 쪽이 이겨서 **이 강조가 나오지 않는다** — "강조되지 않았으면"에 맞는 동작이다. 고른 것은 재킷이 판 전체로 올라오고 판이 도는 것으로 충분히 보인다.
- 재킷 해상도: 새 테마에서는 재킷이 최대 168px 라 `next/image` 의 `sizes` 를 테마에 따라 `168px` / `80px` 로 준다. 이 값만 마운트 뒤에 정해지고(모양은 전부 CSS), legacy 는 `80px` 그대로다.
- 검증: legacy 홈 스크린샷 픽셀 차이 0 · baseline 7/7 · 새 테마에서 재킷 없음/밝은/어두운 재킷과 재생 상태(판 회전 · 톤암 내려옴)를 스크린샷으로 확인. `/dev/theme-lab#turntable-final`.

아래는 결정에 이르기까지의 시안 기록이다. 두 안 중 하나가 정해지면 `LPPlayer` 에 `newtone:` 변형으로 옮긴다(legacy 는 픽셀 단위로 그대로).

### 저장 이미지(취향표 템플릿) — 새 톤 전환 완료 (2026-09-22)

`TasteTemplates` 의 `data-theme="legacy"` 고정을 걷어냈다. 카드가 화면 테마를 따르고, **화면 카드 = 저장 이미지** 원칙은 새 톤에서도 성립한다(같은 페이지의 축소 화면 카드와 오프스크린 export 카드를 같은 배율로 찍어 비교: 평균 차이 2.98/255, 24 이상 차이 나는 채널 2.4% — 전부 축소 리샘플링 오차). legacy 는 기준선 7/7 바이트 동일.

## 8. 구현 메모

- `@theme inline` 의 토큰 값을 `var(--t-*)` 참조로 두고, 실제 값은 `:root`(=legacy) · `[data-theme="toss-white"]` · `[data-theme="sky-tint"]` 에 둔다. `text-navy/70` 은 `color-mix(in oklab, var(--t-navy) 70%, transparent)` 로 풀려 테마를 바꿔도 그대로 먹는다(빌드된 CSS 로 확인).
- `color-mix` 를 모르는 브라우저(Chrome 111 · Safari 16.2 미만)에서는 불투명도 없이 원색으로 나온다. 이전에는 Tailwind 가 계산해 둔 hex 가 대체값이었다. **채택할 때 테마를 하나로 굳히면 값을 다시 직접 적어 이 문제를 없앤다.**
- `<html data-theme>` 는 `layout.tsx` 의 부트 스크립트가 `?theme=` 또는 `localStorage.sortify_theme` 으로 붙인다. 값이 없으면 아무것도 붙지 않아 legacy 그대로다.
- 스크린샷: `node scripts/theme-shots.mjs <폴더>` (dev 서버 3300). Spotify 를 부르지 않는 화면만 찍는다.
