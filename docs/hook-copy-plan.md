# 마음을 건드리는 세부 — 문구·순간 개선 계획

> 2026-09-22 · 통합 책임자 세션 작성 · 사용자 요청: "사용자의 마음을 건드리는 세세한 부분을 어떻게 수정할 수 있을지"
> 기준 문서: `docs/design-system/ux-writing.md` (보이스·원칙), `dialogs.md`, `color.md`
> 상태: **계획. 아직 아무것도 고치지 않았다.** 사용자가 문구를 고르면 담당 세션에 배정한다.

## 0. 한 줄 방향

**"내 취향을 아는 것"이 아니라 "누군가와 취향을 나누는 것"이 후킹 포인트다.**
같이 소트하기가 두 번째 축이 된 지금, 사용자의 마음이 움직이는 순간은 세 개다.

1. 링크를 **받았을 때** — "이 사람이 나한테 물어보네"
2. 결과를 **봤을 때** — "우리가 이만큼 닮았구나 / 다르구나"
3. 결과를 **남에게 보일 때** — "나도 물어보고 싶다"

이 세 순간의 문구가 지금은 기능 설명에 머물러 있다. 사실을 부풀리지 않는 선(ux-writing 원칙 2·4·5)에서
**관계**를 한 단어씩 넣는 것이 이 계획의 전부다.

## 1. ux-writing.md 와의 충돌 — 먼저 정할 것

사용자 예시 `"'아티스트명' 소트에 초대받았어요! 참여하고 서로의 취향을 더 깊이 알아봐요!"` 는 느낌표가 두 개다.
ux-writing 4장은 "느낌표 남발 — 축하 한 곳만 허용", 6장 메타데이터는 "느낌표 없이"다.

| 선택 | 뜻 | 권고 |
|---|---|---|
| A. 규칙 유지 | 초대 제목에만 느낌표 하나(이미 그렇게 돼 있음). 설명은 마침표 | **권고** — 초대는 "축하 한 곳"에 해당한다고 본다. 두 개면 과장으로 읽힌다 |
| B. 규칙 완화 | "초대·공유 문구는 느낌표 최대 2개" 로 ux-writing 개정 | 사용자가 원하면. 개정은 fa 담당 |

아래 제안은 A 기준으로 썼다. B 를 고르면 설명 끝을 느낌표로 바꾸면 된다.

## 2. 순간별 제안

표기: **[현재]** → **[제안]** · 위치 · 담당 · 우선순위(🔴 지금 / 🟡 다음 배포 / 🟢 나중)

### 2-1. 링크를 받았을 때 (카카오톡 미리보기 + 초대 화면 첫 줄) 🔴

여기가 사용자가 짚은 자리다. 지금은 "누가 보냈는지"는 있는데 "왜 하면 좋은지"가 없다.

**미리보기 제목 (og:title)** — `src/app/together/[code]/layout.tsx:46` · 66
- [현재] `{아티스트} 소트에 초대받았어요!`
- [제안] 그대로. 제목은 짧을수록 카톡에서 잘리지 않는다.

**미리보기 설명 (og:description)** — 같은 파일 :47 · 66
- [현재] `{아티스트} 곡 취향이 {닉네임}님과 얼마나 비슷한지 확인해 보세요.`
- [제안 1] `{닉네임}님이 고른 {아티스트} {n}곡, 같이 소트하고 서로 얼마나 닮았는지 봐요.`
  — "고른 n곡"이 구체성(원칙 1·8)을, "서로"가 관계를 준다.
- [제안 2] `{아티스트} 곡을 {닉네임}님과 같은 순서로 소트하게 될까요? 3분이면 알 수 있어요.`
  — 질문형. 소요 시간을 넣으면 진입 장벽이 낮아진다. 단 "3분"은 곡 수에 따라 거짓이 될 수 있어 곡 수 기준으로 계산해 넣거나 뺀다.
- [제안 3 · 사용자 예시 순화] `참여하고 {닉네임}님과 서로의 취향을 더 깊이 알아봐요.`
  — 사용자 문장에서 느낌표만 뺀 것. "더 깊이"는 4장의 꾸밈말 경계에 있지만 뜻을 흐리지 않아 허용 범위로 본다.

**공유 시트에 실리는 문장 (`platform.share` 의 text)** — `src/app/together/[code]/page.tsx:80-81` · 66
- [현재] title `같이 소트하기`, text `{제목} — 같은 곡으로 소트해 봐요`
- [제안] title `{아티스트} 소트에 초대받았어요!`(미리보기와 통일), text 는 og:description 과 같은 문장.
  — 지금은 미리보기와 시트 문장이 달라 두 번 읽힌다. 하나로.

**초대 화면 둘째 줄** — `[code]/page.tsx:194 아래` · 66
- og:description 과 같은 문장을 쓴다(한 곳에서 정의해 세 자리가 같이 바뀌게 — 상수 하나).

**Sortify 를 어디에 넣나** — 사용자: "sortify 를 강조하는 문구"
- og:title 끝의 ` - Sortify` 는 이미 있다(layout.tsx:52). 카톡은 제목 뒤 사이트명을 따로 보여 주므로 본문에 또 넣으면 두 번이다.
- 대신 **미리보기 이미지**가 브랜드를 말한다(로고 B + Nunito 워드마크, 66 작업 중). 문장에 넣지 않는 것을 권한다.
- 넣어야 한다면 설명 끝에 ` — Sortify` 한 번. 문장 안 "Sortify 에서" 는 원칙 2(잡초)에 걸린다.

### 2-2. 이름을 물을 때 (NicknameDialog) 🟡

- [현재] 제목·설명이 "이름을 정해 주세요" 류의 기능 설명(66 구현). 확인 필요.
- [제안] 제목 `일치율에 어떤 이름으로 보일까요?` / 설명 `{방장 닉네임}님이 결과에서 당신을 이 이름으로 봐요.`
  — "왜 묻는지"를 상대와 연결해 말하면 입력이 귀찮은 일이 아니라 관계의 일부가 된다.
- 방장 쪽: `링크에 어떤 이름으로 보일까요?` / `초대받은 사람이 이 이름을 봐요.`
- 담당 66 · 컴포넌트 하나라 두 문구만 바꾸면 된다.

### 2-3. 결과를 봤을 때 (일치율 화면) 🟡

`src/app/together/[code]/result/page.tsx` · 66

- [현재] `평균 일치율 {n}%` · `사람별 일치율` · 혼자면 `아직 나 혼자예요`
- [제안] 숫자 위에 **한 문장의 해석**을 둔다(ux-writing 2장 "결과: 절제된 감정 한 번"). 구간별 한 줄, 과장 없이:
  | 일치율 | 문장 |
  |---|---|
  | 80 이상 | `거의 같은 귀예요.` |
  | 60~79 | `취향이 꽤 닮았어요.` |
  | 40~59 | `반은 같고 반은 달라요.` |
  | 40 미만 | `서로 다른 곡을 아끼고 있어요.` |
  — 낮은 쪽을 "안 맞는다"로 쓰지 않는다(원칙 4). 다름도 결과다.
- **가장 크게 갈린 곡 한 곡**을 보여 준다: `{곡명} — {닉네임}님은 2위, 나는 11위`. 대화거리가 생긴다. 계산은 이미 있는 순위 두 벌로 가능(togetherMatch).
- 혼자일 때: `아직 나 혼자예요` → `아직 나 혼자예요. 링크를 보내면 여기에 이름이 늘어나요.` (빈 상태 규칙: 이유 + 다음 행동)

### 2-4. 결과를 남에게 보일 때 (결과 화면 공유 문구) 🟡

`src/components/result/ResultScreen.tsx:168` · 66 (ux-writing 관점은 fa)

- [현재] `SHARE_CTA = "내 진짜 최애곡을 알고 싶다면? Sortify에서 직접 뽑아보기 👇"`
  — 이모지(4장 금지), "진짜"(부풀림)가 있다. 지금 ux-writing 을 어기고 있는 문장.
- [제안] `내 1위는 뭘까? 직접 골라 보기` (ux-writing 2장 예문 그대로) + 링크.
- 같이 소트하기 결과 공유는 따로: `{아티스트} 취향, {닉네임}님과 {n}% 닮았어요. 당신은?` — 숫자가 후킹이다.
  — 단 "당신"은 5장 용어 사전에 없다. "리스너"로 바꾸면 딱딱하니, 사전에 "당신(공유 문구에서만)"을 더할지 fa 판단.

### 2-5. 진입 문구 (홈·같이 소트하기 첫 화면) 🟢

- 홈 모드 카드 `같은 곡을 각자 소트하고, 취향이 얼마나 닮았는지 확인해요.` — 이미 좋다. 유지.
- `/together` 첫 화면 `같은 곡을 각자 소트하고 얼마나 비슷한지 봐요. 옆 사람에게 받은 코드를 넣어 주세요.` — 유지.
- 곡 고르기 안내 `곡만 정하면 돼요. 소트를 끝내지 않아도 링크를 만들 수 있어요.` — 좋다. 유지.

### 2-6. 미세한 순간들 🟢

| 자리 | 현재 | 제안 | 이유 |
|---|---|---|---|
| 링크 만든 직후 토스트 | (없음 — 화면 전환) | `링크를 만들었어요. 보내면 바로 시작돼요.` | 다음 행동 예고(원칙 6) |
| 참여자가 끝냈을 때 방장 화면 | `지금까지 {n}명이 소트했어요` | `{닉네임}님이 방금 소트를 끝냈어요` (마지막 1명 이름) | 사람이 보이면 다르다 |
| 준비 중 안내 | `이 아티스트는 아직 준비 중이에요. 잠시 뒤에 다시 찾아 주세요.` | 유지. 단 "잠시 뒤" 가 거짓일 수 있음(예산 소진은 다음 날). → `내일 다시 찾아 주세요` 로 사실에 맞추기 | 원칙 1 |
| 로딩(66 공용 컴포넌트) | (작업 중) | `{아티스트} 곡을 모으고 있어요` — 아티스트명을 넣어 기다림에 대상 주기 | 2장 로딩 톤 |

## 3. 하지 않을 것

- 이모지·느낌표 추가·"진짜/완벽/소중" 류 꾸밈말 (ux-writing 4장). 후킹은 **구체적인 숫자와 상대의 이름**으로 한다.
- 문장을 세 자리에 따로 쓰는 것. 초대 문구는 상수 하나(`inviteCopy(artist, creator, n)`)에서 og·share·화면이 같이 읽는다.
- 영어 문구는 이번에 손대지 않는다. 한국어가 정해진 뒤 fa 가 같은 원칙으로 옮긴다.
