# 발매곡 확보 계획 — 빠진 곡을 어떻게 채울 것인가

작성 2026-09-18. 대상은 이용자가 실제로 열 아티스트 784팀(홍보 대상 + 전곡 모드 첫 화면 선정)이고,
그 안의 K-Pop 아이돌 150팀이 1순위다.

---

## 1. 곡 중복 — 해결됨

**증상.** 아이돌은 같은 곡을 정규·리패키지·라이브·중국어판·일본어판·리믹스·인스트로 여러 번 낸다.
앨범 목록은 사실대로지만 전곡 선택과 월드컵에는 같은 곡이 그만큼 들어가 같은 곡끼리 붙었다.

실측(2026-09-18, 자체 DB 기준):

| 아티스트 | 전곡 선택 시 곡 수 | 실제 곡 수 |
|---|---|---|
| EXO | 555 | 230 |
| 방탄소년단 | 439 | 238 |
| 트와이스 | 343 | 242 |

EXO 의 `Monster` 하나가 Live·Chinese version·Instrumental·Remix 로 10번 들어갔다.

**해결.** `src/utils/songKey.ts` 가 아티스트 + 판 표기를 뗀 제목으로 같은 곡인지 가린다.
전곡 선택은 정규 앨범 → EP → 싱글 순, 오래된 것부터 보며 같은 곡을 한 번만 고르고,
월드컵 시작 직전에 한 번 더 거른다. **앨범 화면은 손대지 않는다** — 그 앨범에 실제로 든 곡을 보여준다.

**남은 것.** 제목이 아예 번역된 경우는 아직 못 묶는다 (요아소비 `アイドル` / `Idol`).
MusicBrainz 의 작품(work) 링크로 묶을 수 있고, 트랙리스트를 받을 때 같은 호출에 함께 오므로
`mb_release_track` 에 `work_mbid` 컬럼을 더하면 된다. 홍보 이후 작업으로 둔다.

---

## 2. 빠진 곡은 어디에 있나

빠진 곡을 네 갈래로 나눴다. 갈래마다 채우는 방법이 다르다.

| 갈래 | 규모 | 채우는 법 | 상태 |
|---|---|---|---|
| **A. 아는 앨범인데 트랙리스트가 없다** | 80,428 발매그룹 (우선 아티스트의 정규·EP 11,692) | MusicBrainz 에서 대표 발매판 트랙리스트를 받는다 | 진행 중 |
| **B. 새로 나온 앨범을 아직 모른다** | 현재 0 | mb-worker 가 14일마다 다시 보고, 신보가 감지되면 더 빨리 본다 | 이상 없음 |
| **C. MusicBrainz 에 아예 없는 발매** | Deezer 앨범 28,022 중 17,878 | Deezer 에서 받아 `deezer_*` 에 따로 보관 | 진행 중 |
| **D. 어디에도 없다** | — | 이용자 제보(`unreleased_tracks`) | 기존 기능 |

### A. 트랙리스트 받기 — 가장 큰 덩어리

MusicBrainz 는 IP 당 초당 1회다. 발매판 1개당 호출 1회이므로 80,428건은 22시간이 걸린다.
전부 기다릴 이유는 없다. **중요한 것부터** 받도록 `mb_rg_release.rank` 를 넣었다.

```
rank = (아티스트 중요도 × 10) + 발매 종류
  아티스트 중요도  0 홍보 대상·첫 화면 선정 / 1 한국 / 2 일본 / 3 그 외
  발매 종류        0 정규 / 1 EP / 2 싱글 / 3 그 외
```

| rank | 뜻 | 남은 건수 | 1초에 1건이면 |
|---|---|---|---|
| 0 | 우선 아티스트 · 정규 앨범 | 9,169 | 2.6시간 |
| 0–1 | + EP | 11,692 | 3.3시간 |
| 0–2 | + 싱글 | 25,140 | 7시간 |
| 전체 | | 80,428 | 22시간 |

싱글을 뒤로 미루는 이유는 싱글 수록곡 대부분이 정규·EP 에 다시 들어가고, 그런 싱글은
[1]의 중복 제거가 어차피 화면에서 빼기 때문이다. 한국 디지털 싱글처럼 앨범에 안 들어간 곡은
rank 2 에서 채워진다.

**더 빨리 받아야 하면** 두 가지가 있다. 둘 다 MusicBrainz 규칙을 지키는 범위다.
1. Supabase 엣지 워커(`mb-worker`)에게도 이 대기열을 물린다. IP 가 달라 합쳐서 초당 2회가 된다. 시간이 절반이 된다.
2. MusicBrainz 전체 덤프를 내려받아 직접 읽는다. 제한이 사라지지만 Postgres 100GB 가 필요해 비용에 맞지 않는다. 쓰지 않는다.

### B. 신보 — 지금은 문제없다

우선 아티스트 653팀 전원이 최근 4일 안에 MusicBrainz 기준으로 갱신됐다. 14일보다 오래된 아티스트는 0팀이다.
`mb-worker` 가 매분 돌면서 14일 주기로 다시 보고, 그 사이에 나온 신보는 Spotify 앨범 목록 캐시와 대조해
DB 에 없는 최근 발매가 보이면 14일을 기다리지 않고 다시 본다. 이 경로는 Spotify 를 부르지 않는다.

### C. MusicBrainz 에 없는 발매 — Deezer

한국 디지털 싱글과 최신 발매는 MusicBrainz 등록이 늦다. Deezer 에서 받은 28,022장 중 17,878장이
MusicBrainz 발매그룹과 제목·연도가 겹치지 않는다. 즉 **Deezer 가 아니면 못 낼 앨범이 그만큼 있다.**

한계도 분명하다. Deezer 의 한국 인디 카탈로그는 얇다. 잔나비는 정규 앨범이 한 장도 없고 OST 참여곡만 있다.
아이돌·주류 가요는 잘 채워지고, 인디·밴드는 MusicBrainz 가 낫다. 두 출처를 같이 쓰는 이유다.

**주의.** Deezer 약관은 비상업 이용을 전제한다. 광고 등 수익화를 시작하면 `deezer_*` 네 표를 지우고
그 출처로 나가던 앨범을 화면에서 빼야 한다. 그래서 다른 표와 섞지 않는다.

### D. 어디에도 없는 곡

미발매곡·자작곡은 이용자 제보(`unreleased_tracks`)로 받고 관리자가 승인한다. 기존 기능 그대로 둔다.

## 3. 확보 상태를 보는 법

`artist_serve_coverage` 뷰가 **지금 화면에 실제로 낼 수 있는** 앨범·곡을 센다. 세 갈래를 모두 더한다.

```sql
select name, sp_albums, mb_albums, dz_albums, albums_servable, tracks_servable, release_groups
from artist_serve_coverage where spotify_id = '...';
```

- `sp_albums` Spotify 앨범 ID 가 붙은 MusicBrainz 앨범
- `mb_albums` Spotify 앨범 ID 가 없어 `mb:<발매그룹>` 으로 내는 앨범
- `dz_albums` Deezer 에만 있는 앨범

명단으로 뽑으려면:

```
npx tsx --env-file=.env.local scripts/export-priority.ts   # 우선 확보 784팀 A~F 등급
npx tsx --env-file=.env.local scripts/export-idols.ts      # 아이돌 150팀 확보 현황
npx tsx --env-file=.env.local scripts/backup-catalog.ts    # 전체 DB CSV 백업 (매일 04:30 자동)
```

## 4. 순서

1. **지금** `mb-rg-fill tracks` 를 계속 돌린다. rank 0–1(우선 아티스트 정규·EP) 3.3시간이면 끝난다.
2. 이어서 rank 2(싱글)까지 7시간.
3. Deezer `albums` 단계를 계속 돌려 MusicBrainz 에 없는 발매를 메운다.
4. 홍보 이후: `work_mbid` 를 넣어 번역 제목까지 한 곡으로 묶는다. 엣지 워커에 대기열을 물려 속도를 두 배로 올린다.

## 5. 하지 않을 것

- Spotify 로 트랙리스트를 긁어 채우기 — 앨범 목록 엔드포인트 일일 쿼터가 낮고, 약관이 영구 저장을 금지한다.
- MusicBrainz 전체 덤프 self-host — 비용에 맞지 않는다.
- 멜론·지니·벅스 스크래핑 — 저작권법 제93조·부정경쟁방지법 위반.
- MusicBrainz 의 tags/genres — CC-BY-NC-SA 라 광고를 붙이면 못 쓴다.
